WHAT WAS WRONG

The supplied main file is a merged core. It already contains most final routes and does not define BNX71_ROUTES_. The old zz_FINAL_FIX initializer incorrectly treated a missing legacy registry as a file-order error and threw before time-driven trigger functions could run.

Eight older helper definitions had also been pasted inside doPost's switch, shadowing their newer global definitions. The uploaded file's own PASS82 instructions explicitly called for removing this block. This release removes that nested block and uses the already-present global implementations.

CONFIRMED CORRECTIONS

- No top-level throwing initializer or required PASS71 registry. Optional legacy routes register lazily during authenticated requests.
- Historical read/report actions are not rejected merely because their date is closed. Financial posting locks, session verification and client checks remain in place.
- Added direct GET_TABLE_FLOOR, PING and DSR_ITEM_GROUP_CALC routes.
- Added missing CLIENT_SETTINGS -> MASTER and DEPARTMENT_ISSUE / DSR_ITEM_GROUP_CALC -> TRANSACTION mappings. Those sheets exist in the supplied workbooks; no sheet/header changes are required.
- RD_FETCH_SHEET can read DSR_ITEM_GROUP_CALC. Its TABLE_MASTER cache can no longer answer a different requested tab.
- Item/GST reports normalize percentage and fractional tax-rate formats, preserve stored taxable bases and item tax including explicit zero values, and do not deduct the header discount a second time from a stored base.
- Category lookup accepts MENU_CATEGORY_ID from the supplied master schema.
- GST responses expose CGST_AMOUNT, SGST_AMOUNT and IGST_AMOUNT aliases expected by the dashboard, preserving the existing corresponding values.
- Routine Item Sales and GST reads return live computed data without rewriting report snapshots on every click. persistReport:true opts into snapshot/registry writes. REFRESH_ALL_REPORTS retains snapshot writing explicitly.
- Dataset cache version changed so recently cached calculations from the old implementation are not reused.
- Table-floor reservations accept spreadsheet Date values, live state can link by table ID or table number, RUNNING normalizes to OCCUPIED, and time-only starts handle midnight.
