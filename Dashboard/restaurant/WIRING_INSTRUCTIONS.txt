HOW TO WIRE THIS IN — 3 minutes, zero risk to login
=====================================================

STEP 1 — Add three new files to the BALAJI_NEXTGEN_ERP_V2_CORE project:
  - 40_MasterHubAPI.gs   (paste content from that file)
  - 41_ImportHubAPI.gs   (paste content from that file, created next)
  - 44_OrderEngine.gs    (paste content from that file — unified order engine)

Neither file defines doGet, doPost, or touches login/logout in any way.
They are pure new functions — adding them cannot break anything that
already works, including login.

STEP 2 — Open 09_MainRouter.gs (the router that currently handles
'login'/'logout' and everything else). Find this line:

      /* ---------- UNKNOWN ---------- */
      default:
        return errorResponse('Unknown action: ' + action);

Paste the block below IMMEDIATELY ABOVE that "UNKNOWN" comment.
Do not touch, move, or delete anything else in the file — this is a
pure insertion, nothing existing is edited.

      /* ---------- MASTER HUB ---------- */
      case 'GET_MASTER':
        return MH_getMaster(params);

      case 'SAVE_MASTER':
        return MH_saveMaster(params);

      case 'DELETE_MASTER':
        return MH_deleteMaster(params);

      case 'BULK_IMPORT_MASTER':
        return MH_bulkImportMaster(params);

      case 'GET_PERMISSIONS':
        return MH_getPermissions(params);

      case 'SAVE_PERMISSION':
        return MH_savePermission(params);

      /* ---------- IMPORT HUB (transaction import) ---------- */
      case 'IMPORT_PREVIEW':
        return IH_previewImport(params);

      case 'IMPORT_COMMIT':
        return IH_commitImport(params);

      /* ---------- ORDER ENGINE (POS / Steward / Dine-in / QR / Online) ---------- */
      case 'SAVE_ORDER':
        return ORD_saveOrder(params);

      case 'UPDATE_ORDER_STATUS':
        return ORD_updateStatus(params);

      case 'GET_ACTIVE_ORDERS':
        return ORD_getActiveOrders(params);

      case 'GET_DASHBOARD_SUMMARY':
        return ORD_getDashboardSummary(params);

STEP 3 — Deploy → Manage deployments → Edit (pencil) → New version →
Deploy. Copy the URL if it changed (usually it stays the same for
existing deployments, only the version behind it updates).

STEP 4 — Confirm the URL in master-hub.html and import-hub.html
(near the top of each <script>, look for MASTER_HUB_API_URL) matches
your V2_CORE deployment URL. It's currently set to:
  https://script.google.com/macros/s/AKfycbz39r1zo4LGqHJXpwDsQFulHdp3qsjiLRxRiSIEBBObI_3310_n2izF_gAjofaIHgSJ/exec

This is deliberately kept SEPARATE from your live login URL
(V2_AUTH / ERP_FALLBACK_API) until you confirm whether they're the
same project. Master Hub and Import Hub will work independently of
login either way — worst case, if V2_CORE and V2_AUTH turn out to be
different projects, you just re-point these 2 files to the correct
URL later. Nothing about login is touched by this change.

WHAT THIS DOES NOT DO:
- Does not modify doGet, doPost, loginUser, logoutUser, or any
  existing case in the switch statement
- Does not modify 00_Config.gs, Database.gs, or security-api.gs
- Does not change any deployment currently serving live login traffic
